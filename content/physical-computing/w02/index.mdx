<Entry date="TBD" title="Input · Knob Control">

I connected a potentiometer to Arduino A0 and an MG90S servo to D9 so that turning the knob would control the servo's position. This introduced analog input and mapping: converting a reading of 0–1023 into a target angle.

Printing the reading and target angle together let me compare the code with the physical movement and check the input before troubleshooting the motor.

These experiments build on the [class Arduino tutorial](https://github.com/loopstick/ArduinoTutorial#servo-motors).

<Entry date="TBD" title="Motion · Sweep and Position">

Next, I used the Servo library to make the motor sweep automatically, without turning a knob. The simulation steps through 0–180° and back; the angle steps and delays helped me understand how code controls the pace of movement.

My physical MG90S sometimes kept rotating during wider-range tests. I isolated it and checked fixed commands at 60°, 90° and 120°. It stopped at those positions, so I kept that smaller range for the sensor experiment.

<Entry date="TBD" title="Interaction · Distance to Motion">

I then replaced the knob with an ultrasonic sensor, using hand distance to set the MG90S servo's angle. This linked sensing to physical movement and taught me how the chosen input range affects the response.

At first, the readings changed but the movement was barely visible. Comparing distance and target angle in the Serial Monitor revealed that 5–200 cm was too broad. I narrowed it to 10–30 cm, mapped to 120–60°, and limited each movement step to 2° to soften the transitions.
