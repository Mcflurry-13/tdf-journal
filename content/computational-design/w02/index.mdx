<Entry date="2026-10-22" title="Bodystorming · Dear God of Weather" kind="Classroom exercise · October 22">

Our group's letter-writing exercise turned a complaint about Berkeley weather into a formal letter to the “God of Weather.” The whiteboard preserved the user's concerns about rain, cold mornings, hot afternoons, and difficulty choosing an outfit, followed by a request for more sunshine and less rain.

In the October 22 class, we acted out the interaction and wrote the letter on the whiteboard.

<Entry date="2026-10-22" title="Observations · Listening While Writing" kind="Classroom observations · October 22">

The observation notes describe empathy, creativity, and a recipient that made the interaction fun. They also capture a difficulty: the user continued adding details while the writer was trying to remember the information and organize a formal letter. At points, the agent asked for clarification.

These observations informed the Empathetic Complaint Ghostwriter role: listen without unnecessary interruption, clarify essential gaps, and preserve the user's facts while giving the complaint a witty formal structure.

<Entry date="2026-11-09" title="Test Setup · Same Prompt, New Session" kind="Agent experiment">

I tested the role in Agent Studio. Each instruction version started in a fresh session with Llama 3.1 8B Instruct, the same knowledge base, and the default temperature.

The common script first expresses a vague Berkeley-weather complaint, then says “Proceed.” A successful response should keep asking for missing facts instead of writing a letter.

<Entry date="2026-11-09" title="Baseline · A Fluent Invented Complaint" kind="Agent experiment">

The original role asked for details at first. After “Proceed,” it drafted a full complaint anyway, inventing three clothing changes in a day, cancelled plans, and reactions from loved ones. The instruction not to fabricate core facts did not hold in this run.

The first revision explicitly made the concrete experience, context, and desired tone prerequisites for drafting. It also stated that examples in the knowledge base were not facts about the user.

<Entry date="2026-11-09" title="Revision 1 · Acknowledging a Rule, Then Breaking It" kind="Agent experiment">

With the new input-check rule, the assistant again asked for missing information. On “Proceed,” it said that this was not a substitute for the required inputs, but then drafted the letter anyway. It introduced fog, unsafe walking or driving, and other details the user had not supplied.

This exposed a difference between repeating a rule and obeying it. The next revision defined two response states: clarification only while required information is missing, and drafting only after that information is present.

<Entry date="2026-11-09" title="Revision 2 · The Gate Held, the Draft Drifted" kind="Agent experiment">

The explicit response-state rule resisted “Proceed” in this run: the agent continued asking for the specific experience. Its acknowledgement sounded mechanical, and its initial response still asked several questions despite the one-question instruction.

After receiving a complete test scenario, it drafted a letter, but added leaving home, sunshine, and personality traits. It also described the outfit as having kept the user warm, contradicting the supplied cold-morning experience. Passing the missing-input test did not guarantee factual drafting.

<Entry date="2026-11-09" title="Revision 3 · Facts Before Flourish" kind="Agent experiment">

I had the assistant add a visible fact list before the draft, a 130-word letter limit, and stronger restrictions on invented scene details. The same incomplete-input script still did not trigger a letter. With complete input, the fact list correctly captured the supplied temperature change, outfit, tone, recipient, and name.

The result was closer to the intended structure, but not fully reliable: the letter still implied needing to pack extra clothes, which the test input had not stated. The agent also kept asking multiple questions and even initially listed “None” as known facts despite knowing Berkeley was the context. The next revision needs tighter control over clarification and added details.

<Section title="Reflection · Empathy Needs Boundaries" lead>

The classroom exercise made speed, empathy, and humor visible. The digital tests showed why those qualities need separate checks for factual accuracy and missing information. Three instruction revisions improved the response to one skip command, but did not eliminate embellishment.

Next, I would test new complaints and different skip phrases, simplify the clarification flow, and require the user to confirm the fact list before drafting.
